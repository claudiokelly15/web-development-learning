## Reading the 24 requested dimensions

Each requirement ID has one execution-chain row (dimensions **1–14**) and one assessment row (dimensions **15–24**). Shared profiles below are part of every row that cites them; they avoid repeating long middleware/schema descriptions. The grouped requirements explicitly enumerate constituent capabilities rather than implying an unspecified complete module.

All code paths are relative to `backend/` unless prefixed `../`. Class names without a path mean the exact file under `app/Actions/Payments/`, except merchant workflow classes explicitly identified under `app/Actions/Merchants/`. Controller names mean `app/Http/Controllers/`; auth controllers use `Auth/`. Views mean `resources/views/`. Tests mean `tests/Feature/{name}.php`. Harnesses/fixtures mean `tests/Support/{name}.php`.

### Response/audit conventions

Ordinary auth/merchant/admin responses inherit no-store/private, referrer and framing/nosniff protections as applicable; sensitive exception reporting is redacted. Workflow mutations carry version/request/audit evidence. Financial responses derive from immutable payment/journal/lifecycle records. No response profile implies successful operational execution.
